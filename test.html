Overview

I built a customer segmentation framework from 3 years of transaction data for a digital banking app (Yapeal). The goal was to turn raw transaction logs into actionable customer segments that product and marketing teams can use for personalization and CLV growth. The pipeline: feature engineering → preprocessing → PCA → K-means++ → evaluation → interpretation.

What I delivered:

  • 5 behavioral segments based on customer-level RFM+ features
  • Stakeholder-ready segment definitions (plain-language summaries + visuals)
  • Action guidance (what to do with each segment: retention / upsell / reactivation)

Problems & Solutions

Problem 1 — Customers were treated as one “average user”

User behavior differed significantly across customers, but strategy lacked a clear segmentation model. This limited targeted engagement and CLV growth.

💡 Solution: I engineered customer-level RFM+ behavioral features and segmented users with PCA + K-means++ into five distinct clusters.

Why this matters: product and marketing can focus efforts where the expected CLV lift is highest (retain / upsell / reactivate).

Problem 2 — Statistically valid clusters were hard to interpret

Clusters can be mathematically “good” but still fail if stakeholders cannot understand what each segment represents.

💡 Solution: I characterized clusters using spending scale, frequency, recency, and category patterns, then created clear segment summaries and visuals to make them decision-ready.

Why this matters: interpretable segments reduce adoption friction and speed up experimentation and rollout.

Problem 3 — Insights didn’t translate into clear actions

Even strong segmentation is wasted unless it informs concrete engagement strategies and prioritization.

💡 Solution: I supported an action mapping for each segment (retention / upsell / reactivation) so the segmentation can be operationalized in campaigns and product decisions.

Why this matters: connects analytics to measurable outcomes (activation, retention, and ultimately CLV).

Development Process

1. Framing & success criteria

Goal: identify distinct customer behavior groups to enable targeted engagement and CLV growth.
Definition of success: segments that are (1) stable statistically, (2) interpretable, and (3) actionable for business teams.

2. Data preparation & feature engineering

I transformed raw transactions into customer-level behavioral signals, focusing on RFM+ dimensions: frequency, spending scale, variability, and recency.

Original fields: customer_id, trx_date, amount_chf, orig_currency, category, mcc, counterpart
Output: aggregated customer table with engineered features

  • Frequency: n_tx, median_tx_per_month
  • Scale: total_spend, spend_per_month, median_amount
  • Variability: std_dev_amount, pct_high_value_tx
  • Recency: recency_days
[Customer-level feature set derived from transaction data]

3. Preprocessing (stability first)

Transaction distributions were skewed and heavy-tailed, which can distort distance-based clustering. I applied transformations to stabilize the feature space.

  • Log transform: reduces skew and sensitivity to extreme values
  • Scaling: aligns feature ranges to avoid dominance by high-magnitude variables
[Transformations applied to stabilize clustering]

4. Dimensionality reduction (PCA)

Many engineered features were correlated. I used PCA to reduce multicollinearity and noise while preserving the behavioral signal.

  • Why PCA: improves separability and robustness for distance-based clustering
  • Result: retained 5 components (~95% variance) for clustering
[PCA components retained for clustering]

5. Clustering & selecting K

I applied K-means++ and selected the number of clusters by balancing quantitative metrics with business interpretability.

  • Algorithm: K-means++
  • Model selection: Elbow method + Silhouette score
  • Why K=5: best trade-off between separation and stakeholder-usable segment granularity
[Elbow & Silhouette used to select K]

6. Interpretation (make it usable)

I translated clusters into decision-ready segment definitions using category mix, activity levels, and behavioral summaries.

  • Named and summarized each cluster in plain language
  • Created visuals that compare segments across key features
  • Aligned segment definitions with persona and recommendation work
[Segment definitions for stakeholder communication]

7. Next steps (how this becomes real)

This work is designed to be operationalized—not just presented. A practical rollout would include:

  • Segment refresh: run the pipeline on a schedule (e.g., monthly) and monitor drift
  • Experimentation: A/B test segment-targeted messaging and offers and track CLV lift
  • Iteration: expand features with non-transaction signals (app usage, support events) if available

Original fields: customer_id, country, type, trx_date, amount_chf, orig_currency, category, mcc, counterpart
Aggregation: customer-level summarization across time
Derived feature groups:

  • Spending variability: std_dev_amount, pct_high_value_tx

3. Preprocessing for stable clustering

Transaction features were heavily skewed (e.g., spending scale). To avoid unstable distance-based clustering, we applied transformations and normalization.

  • Log transform: reduced skew on heavy-tailed variables
  • Scaling: Min–Max scaling to align feature ranges for K-means distance calculations
  • Quality checks: distribution review and outlier sanity checks
[Log transform and scaling to stabilize clustering]

4. Dimensionality reduction (PCA)

Many engineered features were correlated. PCA helped remove redundancy and noise while keeping most of the behavioral signal.

  • Why PCA: reduce multicollinearity and improve cluster separability
  • Result: retained 5 principal components explaining ~95% of variance
[PCA components retained for clustering]

5. Clustering (K-means++) & model selection

We applied K-means++ and chose the number of clusters with a balance between statistical quality and business interpretability.

  • Algorithm: K-means++
  • Selection: Elbow method + Silhouette score
  • Decision: K = 5 as the best trade-off between separation and interpretability
[Elbow & Silhouette used to select K]
